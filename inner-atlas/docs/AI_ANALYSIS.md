# DeepSeek 综合分析：设计、提示词、知识库与部署

版本：提示词`2026-11-15.2`，知识库`2026-11-15.2`，输出协议`1.0`。核对日期：2026-11-15。

## 用户最终看到什么

报告入口为“AI 综合分析”。分析整个答卷的共同主题、关系差异和矛盾，不把每道题逐一换成一句性格评语。输出：

- 一份连贯的整体画像和2–5个跨领域主题。
- 12个章节：整体人格动力、核心关系需要、恋人、朋友、家庭、冲突边界修复、情绪与自我、优势资源、盲点代价、近期状态与评估方向、改变、未知。
- 0–3条待验证循环：可能触发—理解—保护性应对—短期作用—可能代价。没有资料时不强行生成。
- 0–4项真实存在的张力，每项至少两种解释；2–3个具体小行动；3–6个继续追问的问题和具体未知。
- 先看整体和主题，再按需展开12项细节；默认展开有资料的关系章节。支持全部展开、索引定位和打印全章。
- 每个主题可点“这点不符合我／补充反例”，定位并填入补充入口；旧报告标为过期，重新授权后才再次发送。
- 支持资料可展开，区分量表、原创题、情境和个人自述。导出包含引用。

这些是有依据但仍可能有误的自我理解假设，不是临床诊断或已经观察到的全部人生。

## 已写好的文件

- `ai/system-prompt.md`：完整中文综合分析提示词；规定综合方法、反例、替代解释、未测领域、心理健康及提示注入边界。
- `ai/review-prompt.md`：第二轮编辑指令，检查反例、对象范围、资料对应、套话和健康解释边界，必要时整体改写。AI复核不等于独立临床审核。
- `ai/knowledge/psychology.v1.json`：24条有来源ID的策划知识短摘要；依托原有32条来源记录。小库全量放入上下文，不冒充向量检索、全文图书库或系统综述。
- `src/ai-contract.js`：12章输出协议与引用检查；重大结论要求不同领域资料。不同领域不等于统计独立。
- `api/analysis.mjs`：服务端从原始回答重新计分，建立证据台账、施测覆盖、缺失状态和发送包。
- `api/deepseek.mjs`：官方API调用，JSON解析及报告检查。不返回供应商内部推理内容。
- `api/http.mjs`：仅服务端持有密钥；访问口令、来源白名单、请求大小、并发与每小时额度。
- `src/ai-ui.js`：发送范围预览、单独健康授权、背景与反例、综合报告、引用和导出。

```mermaid
flowchart LR
 A[完整答卷与可选背景] --> B[本地预览及明确授权]
 B --> C[服务端校验与重新计分]
 C --> D[证据台账与覆盖情况]
 D --> E[综合提示词与24条知识摘要]
 E --> F[DeepSeek整合初稿]
 F --> G[JSON结构与引用检查]
 G --> R[第二轮AI质疑与编辑]
 R --> V[最终结构与引用检查]
 V --> H[综合画像与12章解释]
```

开始答题前和AI报告页会读取后端状态；检测不含答卷、背景和访问口令。状态“已配置”只代表后端报告配置完成，不验证供应商密钥有效性、余额或模型质量。关闭或不可用时暂停AI提交；本地探索仍可进行。修改后端地址后需要重新检测，状态恢复不会自动上传答卷。

至少完成70%基础题、3个人格维度、总体依恋、4个原创探索维度及3个情境，才开放综合调用。缺失与关闭的关系不外推；健康未经授权不推断。修改答卷、背景或健康共享选项后，旧报告标记失效；请求过程中资料改变，返回结果会丢弃。

## 数据和隐私

默认仍是本地计分，不自动调用AI。用户主动确认后，浏览器向分析后端发送所选范围的题目ID和数字回答、模块开关、可选背景、成人与发送授权。后端补充题意和重新计算的分数后调用DeepSeek。**并非只发送“匿名分数”**，自由背景也不能保证无个人信息；界面允许逐项预览并提醒不填写身份信息。

PHQ-9、GAD-7、PCL-5需额外勾选共享；否则这些题的答案和分数不会随请求发送。改变勾选不撤回已发送内容。访问口令放请求头，不放URL，也不是DeepSeek密钥。

应用后端不主动写入答卷、背景或报告正文，不设置请求体日志或数据库。服务主机、反向代理、监控系统和DeepSeek可能有各自的请求处理／留存规则，因此不能承诺零留存。部署者应核对平台日志与数据政策。[DeepSeek开放平台隐私政策](https://cdn.deepseek.com/policies/zh-CN/deepseek-open-platform-privacy-policy.html)。

AI报告、背景和访问口令仅保留在页面内存，不写入原始答题备份。刷新后不恢复AI报告；可导出Markdown或打印。清除答题同时取消等待并清除AI内存。模型文字以纯文本转义显示，不执行HTML或脚本。

## 本地启用

需要Node.js 22及以上，无npm运行时依赖：

```bash
cp .env.example .env
# 在自己的设备编辑.env，填写下面的服务端配置。不要把密钥发送到聊天。
npm run doctor
# 检查通过后
npm start
# http://localhost:4173
```

默认每次分析包含两次模型调用：整合初稿与复核编辑，不是失败后的自动重试。复核失败时不退回展示初稿。两次调用共用240秒总时间预算；前端等待255秒。

服务端环境变量：

| 名称 | 含义 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 自己在DeepSeek开放平台申请的密钥，只在后端设置 |
| `DEEPSEEK_MODEL` | 默认`deepseek-flash`，也支持`deepseek-v4-pro` |
| `DEEPSEEK_REVIEW` | 默认`true`，第二轮复核；显式设`false`可单轮生成，报告会标明单轮 |
| `ANALYSIS_ACCESS_TOKEN` | 独立随机访问口令，至少24字符；不是API Key |
| `ALLOWED_ORIGINS` | 允许访问的完整origin，逗号分隔，例如`https://wangkeyu-u.github.io`，不含仓库路径；通过HTTPS代理部署本应用时也填入自己的公开origin |
| `AI_REQUESTS_PER_HOUR` | 单实例每小时请求尝试上限，默认6；并发上限1 |
| `PORT` | 默认4173 |

可以用自己终端中的`node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"`生成访问口令，再填入后端环境设置。该命令只在自己的环境执行，不需要贴出生成结果。网站中“分析服务与访问设置”只填写这个访问口令。

后端未设置密钥、口令或有效模型时会明确返回未配置；本地普通结果仍可使用。`GET /api/status`可检查是否配置完成，不返回密钥或口令。

## GitHub Pages加独立后端

GitHub Pages只托管静态文件，不能保存或执行DeepSeek密钥调用。

1. `npm run build`产生的`dist/`放到GitHub Pages。
2. 在支持Node长请求或容器的服务器部署完整项目。已提供`Dockerfile`；不绑定任何Sites服务。
3. 在后端平台设置密钥、随机访问口令和前端origin；使用HTTPS。配置反向代理允许至少300秒处理时间。
4. 网页“分析服务地址”填写`https://你的后端/api/analyze`。同站点由本Node服务托管前端时可留空。
5. 后端通过真实HTTPS检查后，再用自己自愿提供的测试答卷验证模型内容。不得把自动化测试的模拟文本当作真实DeepSeek报告。

容器方式示例（自行准备.env，不把它构建进镜像）：

```bash
docker build -t inner-atlas .
docker run --rm --env-file .env -p 4173:4173 inner-atlas
```

当前限额和并发控制在单进程内存中，重启会重置，多实例不共享。访问口令是简易私人站点门禁，不是多用户账户或硬性费用上限；规模化公开服务应增加正式身份验证、持久限流和供应商侧预算控制。本次未部署或测试这些扩展设施。

## 官方API核验

核对了[首次调用](https://api-docs.deepseek.com/quick_start)、[当前模型](https://api-docs.deepseek.com/quick_start/pricing/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)和[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

默认使用`https://api.deepseek.com/chat/completions`，模型`deepseek-flash`、thinking enabled、high effort、JSON object、每次调用最多24576输出token。未沿用旧`deepseek-chat`或`deepseek-reasoner`名称。Thinking模式不设置无效的temperature参数。忽略并不返回`reasoning_content`；只展示用户可核实的结论和证据。

空白、截断、非法JSON、缺章、无效引用、同领域证据冒充跨领域结论、未施测领域假装有结论或明显诊断越界的输出会拒收；不静默补造，也不在失败后自动重试。默认的第二次调用是有意安排的编辑复核，仍会产生模型费用；两轮均由站点提供者的API账户承担。自动检查是有限防线，不能验证语义支持、临床有效性或完全消除幻觉。

## 本轮优化的适用范围

增加服务端生成的关系差异表、时间范围与背景／反例定位，帮助模型整合。差值仍只是原始自报均值差；不赋予统计显著性或因果解释。24条知识中补充了对应的整合检查项，没有宣称新增临床研究。

复核阶段只接受明确保留或整体改写；改写结果仍须通过同一组引用与结构检查，未知引用、重复引用或不完整复核均拒收。不把多次模型输出当成独立证据，也不把流程验证当成分析准确性的证明。
