# 测试后的继续追问

生成综合报告后，点“继续问 AI”。可以问人格主线、恋人／朋友中的差别、建议怎样落地，也可以补充反例、指出报告哪里不符合。继续使用原来服务端的DeepSeek密钥，不需要访客另填Key。

## AI会参考什么

每次发送都带上本次已授权的原始回答、重新计分、补充背景、综合报告和当前这段完整对话。报告是可修订的解释，不是已观察到的事实；新补充优先用于核实和收窄旧判断。原始分数及报告不会因聊天自动改写，修改答卷或背景后需重新综合。

聊天只保存在当前页面的内存中，没有加入浏览器持久存储或后端对话数据库。刷新后不保留；关闭前可点“下载追问记录”。一段最多12轮，或历史超过36,000字符时提示下载、清空再继续；不会悄悄丢掉前面的对话。清空对话仍保留本次答卷和报告；清除全部答题数据会一起清除对话。

## 链路与边界

`POST /api/chat`复用原来的访问设置、来源控制、公开朋友模式和并发限制。后端重新构造获授权资料并核对`inputHash`，验证旧报告引用，避免把变化后的答卷当作旧记忆继续回答。追问最多1500字，历史角色严格交替；聊天请求体上限384KiB，分析请求仍64KiB。

每次追问一次官方DeepSeek请求，180秒后端预算、195秒页面等待，没有自动重试；沿用JSON空白保活。HTTP200中若有显式错误code仍按失败处理，不展示截断或半份回答。取消、过期返回、服务错误不会加入半轮历史，失败问题保留供用户处理。模型内部推理与Key不返回前端。

输出必须为JSON答复及真实相关引用，模型文字以纯文本显示。有限内容检查不等于临床验证或句子级真伪验证；不能诊断、推隐藏创伤或用八维算功能栈。是否带健康资料沿用本次报告授权；健康选项改变会使记忆失效。追问文本中新主动提供的敏感信息也会随问题提交，发送前页面有提示。

## 配置与检查

不新增密钥。可选`AI_CHAT_REQUESTS_PER_HOUR=24`，与默认每小时6次分析额度分别计数，两者共享最多1个进行中的请求。额度全站共享，清空对话不重置额度。`npm run doctor`也检查追问额度格式。

`npm test`包含记忆与答卷对应、健康隔离、角色注入、轮数、历史、旧报告传递、单次调用、引用、截断、诊断越界、原有访问控制、独立额度、保活错误及代理路径。`tests/ui_chat.py`用模拟上游验证报告到两轮追问、纠正信息、纯文本、失效禁用、取消／失败、清空不清题、导出、12轮上限、手机与桌面宽度、全部数据清除。模拟测试不消耗真实API。

```bash
node tests/mock-ai-server.mjs
AI_PREVIEW_URL=http://127.0.0.1:4175 python tests/ui_chat.py
```

真实检查另行记录在本文末尾，不把记录回放当作新的模型生成。


## 本次真实检查

[查看原始续聊与定向复测](CHAT_REAL_RECORD.md)。使用已记录的真实周岚报告回放进入页面，再作两次真实DeepSeek追问，耗时11.5秒、8.2秒。第二次请求包含第一轮完整问答；AI准确复述“对方上班／周末”两个场景，并据此收窄了旧画像。当前答卷和报告每次都随请求，原分析没有重复计费。

两次请求体分别36,928、39,240字节；公开手机尺寸浏览器在360／390／768／1440像素无横向溢出，页面错误0，记录下载通过。它验证链路与这个案例的记忆，不证明所有回答都准确。

第一轮发现：模型附加了与问题无关的健康结尾，又把“工作时较少交心”延伸到其他习惯。已在续聊提示词增加“只修订新资料直接支持的判断”及“不主动添加无关健康结尾”。随后对同一第一问单独作一次真实后端回归（12.4秒），没有再次附加筛查结尾，并进一步区分对象与时段；这不是第三轮连续对话或新的网页全流程。

三次真实追问调用合计77,431个提供方token，没有自动重试。仍有“时间紧时更容易怎样”等解释性措辞，不能自动当作实际频率或因果；用户可以继续补反例。提示词与字段检查不能保证完全消除语义越界。
